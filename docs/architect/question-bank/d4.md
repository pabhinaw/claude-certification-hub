<p class="qb-meta"><span class="qb-id">D4-044</span><span>Batch processing</span><span>Claude Code in CI/CD</span><span title="Difficulty">●●○</span></p>

A team is considering the Message Batches API. Which TWO workloads suit it? (Select TWO.)

- **A.** A weekly audit report that nobody is waiting on
- **B.** Nightly generation of test suggestions for the next morning
- **C.** A pre-merge check that blocks developers until it finishes
- **D.** A multi-turn tool-calling loop inside a single batch request
- **E.** A live chat reply to a waiting customer

??? success "Answer: A and B"
    **Why A is right:** Non-blocking work fits an asynchronous, cheaper API.

    **Why B is right:** Results are needed hours later, not immediately.

    **Why the others are wrong:**

    * **C:** Batches have no latency guarantee; blocking checks need synchronous calls.
    * **D:** A batch request is a single call; it cannot run a tool loop.
    * **E:** A waiting user cannot tolerate batch delays.
