<p class="qb-meta"><span class="qb-id">D2-001</span><span>MCP scope</span><span>Developer productivity</span><span title="Difficulty">●●○</span></p>

The team's issue-tracker MCP server must be available to everyone who clones the repo, and it needs an API token. What is the right setup?

- **A.** Project scope .mcp.json, with the token referenced as ${TRACKER_TOKEN}
- **B.** Project scope .mcp.json with the token hard-coded so setup is automatic
- **C.** User scope, with the token stored directly in each person's ~/.claude.json
- **D.** Local scope on each laptop, with setup steps documented in the README

??? success "Answer: A"
    **Why A is right:** Shared means project scope; secrets go through env-var expansion.

    **Why the others are wrong:**

    * **B:** Leaks a secret.
    * **C:** Not shared.
    * **D:** Not shared.

- **A.** Rename them search_a and search_b so the names no longer suggest overlapping purposes
- **B.** Expand both descriptions: what each covers, when to use it, and when to use the other
- **C.** Merge them into one tool with a 'type' parameter, with no other change
- **D.** Set tool_choice to auto so Claude weighs both tools more carefully on each turn
