<p class="qb-meta"><span class="qb-id">D1-001</span><span>Prerequisites</span><span>Customer support agent</span><span title="Difficulty">●●○</span></p>

A retailer's support agent occasionally calls process_refund before verify_customer. Policy says identity must be verified first. What is the MOST reliable fix?

- **A.** Gate process_refund in code so it returns a precondition error until verification succeeds
- **B.** Switch to a larger model
- **C.** Add 'ALWAYS verify the customer first' to the system prompt in capital letters so the rule stands out
- **D.** Add a few-shot example to the prompt showing verification happening before every refund

??? success "Answer: A"
    **Why A is right:** Ordering that matters must be enforced in code, not prose.

    **Why the others are wrong:**

    * **B:** Doesn't address the missing enforcement.
    * **C:** Improves the odds; guarantees nothing.
    * **D:** Guides behaviour; doesn't enforce it.

<p class="qb-meta"><span class="qb-id">D1-006</span><span>Agent loop</span><span>General</span><span title="Difficulty">●○○</span></p>

An agent loop must decide whether to keep executing tools or return a final answer. Which signal should the code use?

- **A.** Whether the reply text contains a completion phrase such as 'Task complete'
- **B.** The response's stop_reason: continue on tool_use, finish on end_turn
- **C.** A fixed number of iterations chosen per task type
- **D.** Whether the response contains any text block at all

??? success "Answer: B"
    **Why B is right:** stop_reason is the structured, reliable signal. tool_use means Claude is waiting for tool results; end_turn means it has finished.

    * **C:** An iteration cap is a safety limit, not a completion signal.
    * **D:** Responses can contain text and tool_use blocks together; text doesn't mean the task is done.

- **C.** Send an empty tool_result so the conversation history stays valid and the loop continues
- **D.** End the session immediately with an error page

??? success "Answer: A"

- **A.** It isn't needed if stop_reason is checked correctly
- **B.** To stop runaway loops; reaching it should trigger a handled outcome such as escalation
- **C.** To make sure the agent finishes within one API call
- **D.** To save tokens; when it's reached, the last response is returned to the user as the answer

??? success "Answer: B"
