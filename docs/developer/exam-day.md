# Developer Exam Day Guide

## The day before

* Read the [cheat sheet](cheat-sheet.md) and your miss log once. No new topics.
* Confirm your appointment time and time zone, and that your ID matches your registration name exactly.
* Online proctoring: run the provider's system check on the same computer and network you will use. Clear your desk and plan for a quiet, private room.
* Test centre: check the route and aim to arrive early.
* Sleep. It is worth more than a late revision session.

## Pacing

53 questions in 120 minutes is a little over **two minutes each**, which is comfortable if you don't stall.

| Pass | Aim |
|---|---|
| First pass (about 75 min) | Answer everything you can. Flag anything that takes more than two minutes, choose your best guess, move on |
| Second pass (about 30 min) | Return to flagged questions with a fresh eye |
| Final check (about 15 min) | Confirm nothing is blank and every multiple-response item has the right number of selections |

Never leave a question unanswered.

## Reading a question

1. **Read the last sentence first.** It tells you what is being asked: the *cause*, the *first step*, the *most cost-effective* option, the *most reliable* one.
2. **Find the constraint.** A waiting user, a hard rule, a budget, a shared team: the constraint usually picks the answer.
3. **Predict before you look.** Decide what a good answer would be, then find the option that matches.
4. **Eliminate.** Usually two options are clearly wrong. Decide between the remaining two on the constraint.

## Multiple-response questions

* Note **how many** to select and select exactly that many.
* Treat each option as its own true/false statement. Mark each mentally before combining.
* Don't look for a "matching pair". The correct options need not be related to each other.
* Assume no partial credit and take the extra seconds to check each option.

## Patterns in wrong options

| Pattern | Example |
|---|---|
| **Prompt as enforcement** | "Add a strongly worded instruction" for a rule that must never be broken |
| **Bigger hammer** | "Use the largest model" for a design or data problem |
| **Unbounded** | "Retry until it succeeds" |
| **Wrong lever** | "Lower the temperature" to fix truncation, access control or cost |
| **Silent failure** | "Return an empty result so the flow continues" |
| **Over-engineering** | A multi-agent system or an MCP server for a simple, single-use task |
| **Misplaced secret** | Key in the client, the prompt or the repository |
| **Real feature, wrong job** | Batch for a live chat; streaming to cut cost |

If an option shows one of these, it is very likely a distractor.

## When you are unsure

* Prefer the answer that fixes the **cause** over one that treats the symptom.
* Prefer **deterministic** controls for hard requirements.
* Prefer the **simplest** design that meets the stated need.
* Prefer **least privilege**.
* Prefer answers that **surface** errors over ones that hide them.
